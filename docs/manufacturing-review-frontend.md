## Workflow

Checkout configuration consent is separate from manufacturing approval. New orders preserve the configuration and protected manufacturing evidence read at checkout; administrator order details show that saved snapshot rather than the latest product. Public cart/receipt disclosures do not claim that a legacy product has approved measurements, rights or profitable pricing. This slice does not change original product prices, review flags or publication state.

1. Open an existing saved product. An active unflagged product must first be explicitly unpublished and saved before starting review. For a product already flagged for review, **إلغاء نشر المنتج لبدء المراجعة** sends only `{ isActive: false }`, without unrelated form changes. Starting review, unpublishing, approving and publishing are separate actions.
2. For an unflagged inactive product, use **بدء مراجعة التصنيع** only when the editor is clean, successfully loaded and has no save/upload in progress. This calls `POST /api/admin/products/:id/manufacturing-review/start` with only `{ expectedUpdatedAt: product.updatedAt }`, using the exact saved timestamp. The backend preserves the product's prices, specifications, media and provenance while initializing revision 0, pending status, blank references and null measurement/cost inputs. It records a server-owned `started` history event. A fresh request for an already flagged inactive product returns its existing review unchanged; an old timestamp receives 409. The enrollment does not approve or publish the product.
3. Enter measured filament consumption, finished weight and printing hours. Enter the selected material, confirmation that consumption includes supports and waste, hourly machine/electricity costs, per-piece costs, rates and rounding choice. Missing numeric, enum and consumption-confirmation values start as `null`; references start empty. An explicit zero cost remains zero. Existing product weight, print time, material and price are not converted into review inputs.
4. Record measurement, sample inspection and model/image rights references. **حفظ بيانات المراجعة** saves the complete editable review with its expected revision. An incomplete review may be saved. Saving returns it to pending and clears previous approval.
5. **حساب التسعير من الخادم** quotes the saved revision. Unsaved review or product edits block quoting. The panel displays all server breakdown entries, material rate, target/achieved margin, rounding, effective selling price and exclusions. **الربح المتوقع عند السعر المحسوب** explicitly refers to the target price, not the adjacent current selling price. Shipping is excluded and taxes are not calculated. The calculated quote alone is not manufacturing approval.
6. If the effective selling price is below the quoted target, choose a price in the ordinary product editor and save it while inactive. The effective price includes a discount when present. Price/specification/media changes invalidate the previous review approval; calculate a fresh quote afterward. The panel never applies the quoted target to the product itself.
7. Confirm all three explicit attestations: sample inspection, rights review and pricing approval. Approval also requires complete references, matching product/costing material and a server quote that the current price meets. The request carries the current server revision and fingerprint. Reviewer identity and approval time remain server-owned.
8. An approved review leaves the product inactive. Publication is a separate action in the existing product editor, subject to product validation and backend publication guards. Changes to reviewed price, specifications or media require unpublishing first and a new quote/approval before republishing.

## State and failure handling

- The component uses signals and bridges reactive form events with `toSignal`, including dirty state and attestations. Templates and styles are external; options, field definitions, labels and form factories are in the companion control file.
- Review inputs and product fields have separate save operations. Unsaved review inputs block product saves; unsaved product inputs block review operations. A separate local-discard action releases this state without dropping the product editor's changes. Product fields typed while a review request is pending are preserved when its response arrives; server publication state is retained.
- Enrollment also blocks duplicate submissions and product writes while pending. Product fields typed during the request survive its response. A stale or uncertain enrollment result retains local edits and blocks another enrollment/product save until explicit **تجاهل التعديلات وإعادة تحميل المنتج** succeeds. That action clearly discards local edits when the current server product loads; a failed reload preserves them and keeps writes blocked. The client does not assume a failed response means enrollment failed on the server.
- Editing review inputs clears the displayed quote and new attestations. Saved approval status, revision, date and a concise history are shown separately. Private actor IDs and fingerprints are not displayed.
- Normalized API errors use `statusCode`. A 409 retains local inputs, clears the quote and requires an explicit server reload before another write. The reload action states that unsaved review inputs will be discarded. Validation errors identify the affected fields in Arabic; loading and uncertain-result states do not report a successful save.
- Local validation permits incomplete drafts while rejecting supplied nonpositive measurements, excessive decimal precision, negative costs and invalid percentages. The server remains authoritative for completeness, arithmetic, reference checks, stale writes, rights and publication.
- The panel sits outside the product editor's form, avoiding nested forms. Responsive field grids collapse to one column on narrow screens; controls have labels, focus styles, status/error announcements and touch-sized actions.
