## Products

- Products list, search, category/featured/sort filters, server pagination, row actions, confirmation dialog and file preview now use Arabic labels in the calm shop palette. Mobile table rows become cards, with 40px minimum action targets and contained pagination. Existing server pagination is preserved; page two is not sliced a second time.
- Preview fetches current admin product data and shows loading/error/retry states. A failed fetch does not quietly substitute a stale cached product. Image preview reports a broken URL; the existing shared 3D viewer remains responsible for loading, controls and recovery.
- New products begin unpublished with publication disabled, with no guessed category, material, finish, weight or manufacturing duration. The API enrolls every new product and copy in manufacturing review; explicit active creation is rejected. Material is explicitly selected; category is explicitly selected or entered by the operator. An inactive draft can have price zero and incomplete measurements; publishing requires approved manufacturing/sample/rights/pricing review, a positive price and the existing description/specification requirements. Saved new/copy drafts open the same review panel as imported candidates. Existing legacy publication/review flags and prices remain unchanged. The backend remains authoritative for publication review.
- Category filters now use `GET /api/admin/products/categories`, with typed `{ name, productsCount }` records from all non-deleted active and inactive products. They include actual draft categories instead of relying on the old fixed choices or the public active-only endpoint. The selected filter remains available after a failed request or a changed response; errors support explicit retry. Successful deletion refreshes category options. A category literally named `all` remains filterable because the all-categories option uses an empty value.
- The editor merges established choices, real API categories and its current value without duplicates. A loaded custom category remains visible while options load or fail, and unrelated saves preserve it. Late responses do not replace unsaved operator input. Existing choices and explicit custom entry keep first-product creation possible when the store has no categories. Product/form category contracts now accept strings, matching the backend; known labels remain presentation data. Label lookup checks own properties, preserving custom names such as `constructor` and `__proto__` as text in options and the product table. No taxonomy or stored category was automatically remapped.
- Image selection checks JPEG/PNG/WebP and the existing 10 MB server limit. Model upload validates the supported extension and existing 100 MB limit. Failed model uploads preserve the previous URL and format. Gallery results report successful uploads, and editable URL fields update preview state. Upload success tells the operator to save the product.
- Save-and-continue retains the created ID for subsequent PUT requests. Editing preserves the slug unless explicitly changed. Arabic letters/numbers are supported in canonical slugs. Only saved published products offer a public preview link. Duplicate creates the backend's inactive draft; deletion requires explicit confirmation.
- AdminProductService uses real API requests only; removed unused mock/storage methods and the core ProductService dependency. Responses normalize Mongo IDs, editable payloads omit generated imageVariants metadata, and backend image derivation remains authoritative.

## Settings

- Settings now expose fields that currently affect the store: name/description, actual contact/social channels, shipping fee/estimate and temporary order intake control. Dormant hero/address/policy fields are preserved from the loaded server object during PUT rather than overwritten or presented as working controls.
- Egyptian mobile input supports local, +20, 0020 and Arabic digit formats. WhatsApp is saved as 20-prefixed digits; contact phone is normalized to +20 and accepts Egyptian landlines. Optional blank channels stay blank. Email and HTTP(S) links are validated; embedded URL credentials are rejected.
- EGP is fixed to the configured store currency. A blank delivery fee remains null/unconfirmed, while zero explicitly means no delivery charge. No shipping price or duration is invented. The temporary stop control accurately describes the backend behavior: new product orders are rejected while the catalog remains available.
- The current admin settings must load successfully before editing/saving. A failed save preserves edits and asks the operator to reload saved values before retrying. Discard resets to the loaded snapshot without writing. There is no destructive reset-to-defaults action.
- AdminSettingsService begins from the same DEFAULT_ADMIN_SETTINGS on server and client, without any localStorage access. Public GET uses real HTTP (compatible with root SSR transfer caching); failure resets blank defaults. Private admin GET failures propagate to the blocking UI. No fake-success mock branches remain.

## Standards

Components remain standalone with external templates/styles, inject(), signal/computed state and DestroyRef cleanup. Typed contracts/enums and companion control/data files hold form choices and validation configuration. Templates bind derived signals rather than run transformations. PrimeNG receives Arabic translations in its existing lazy route initializer.
