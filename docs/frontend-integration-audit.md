## Historical highest-priority findings

1. **Guest checkout could not finish:** `src/app/features/cart/pages/cart-page/cart-page.component.ts:108` redirected unauthenticated shoppers to login, discarded delivery form state, and always navigated to the protected orders route after creation. The backend accepts guest orders. Implement a guest receipt with a private tracking token, preserve tab-scoped details, and make account sign-in optional.
2. **Checkout retries could duplicate orders:** the same component had no idempotency key and opened WhatsApp only inside an asynchronous callback, which browsers can block. Preserve an idempotency key for a pending submission and render a usable confirmation with a normal support link. Backend must calculate authoritative totals.
3. **Shipping could look free before confirmation:** `OrderService.normalizeOrder` defaulted missing shipping to numeric zero with no confirmation flag. Display unconfirmed shipping explicitly; incorporate the backend `deliveryFeeConfirmed` field.
4. **Egypt-only validation was absent:** the checkout accepted virtually any 8–20-character phone string and arbitrary international data. Normalize Egyptian mobile formats, provide the 27 governorates, and submit country `EG`. Backend must enforce the same requirements.
5. **Rotated refresh tokens were discarded:** `src/app/core/services/auth.service.ts:116` saved only the returned access token. Save both tokens using a declared response interface. The error interceptor currently redirects immediately on 401 rather than refreshing; startup also has no caller of `loadCurrentUser`.
6. **Admin preview and validation computed values are stale:** `src/app/features/admin/pages/product-form/admin-product-form-page.component.ts:153` and following computed declarations read Reactive Forms values with no signal dependency. Angular computed values therefore do not rerun when the form changes. Convert form `valueChanges`/`statusChanges` to signals and derive previews/error summaries from those signals.
7. **Order operations are missing from admin navigation:** `src/app/features/admin/admin.routes.ts` only exposes dashboard, products and settings, despite backend endpoints for orders, custom orders and contact messages. A sales-ready store needs fulfillment/status management and customer-request handling.

## Historical other functional and performance gaps

- `products-page.component.ts:onSearchChange` sends a request for every keystroke, without debouncing or cancellation. Overlapping responses can show results for an earlier query. Use a debounced signal/observable and `switchMap`, persist filters/pagination in the URL, and distinguish errors from empty results.
- Product details also permits overlapping route fetches, retains quantity across product navigation, and derives related products from the last cached catalog subset instead of querying the category.
- `CartService` trusts stored JSON shapes and permits invalid quantities through its public methods. Validate cached cart entries, clamp quantities and handle storage exceptions.
- Settings, products and token services assume localStorage is always available. Several reads/writes can prevent app initialization in restricted storage contexts.
- Admin settings/product edit error handlers fall back to cached values without making failure clear, risking edits of stale data.
- Development and production environment files had different support phone numbers; `angular.json` had no environment file replacement, so production used development environment values.
- Missing teardown across admin/auth/contact subscriptions and extensive existing `readonly` fields violate the supplied standards. `admin-product-form-page.component.ts:522` uses `unknown`; inline contract object types and hardcoded spec arrays remain.
- Forms and ordering were predominantly English and dark-themed; Egypt-first Arabic/RTL content and accessible calm colors are required.
- No evidence yet establishes complete browser coverage, checkout fulfillment, real payment handling, production analytics, or Lighthouse scores of 100. Build/test execution cannot prove these business requirements.
