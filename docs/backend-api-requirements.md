                        ## 1. General Overview

                        **3D Otaku** is an anime-style 3D e-commerce platform specializing in 3D printed anime models, decorative cosplay props, swords, daggers, display collectibles, and custom requests.

                        Key features handled by backend APIs:
                        - User authentication & role management (Customer & Admin roles).
                        - Product management, categories, filtering, pagination, search, active/inactive toggle, soft deletion, and product duplication.
                        - Interactive 3D model (`.glb`, `.gltf`, `.stl`, `.obj`, `.ply`) and image file uploads.
                        - Custom order requests & contact message submissions.
                        - Admin dashboard metrics and operational statistics.
                        - Dynamic global site configuration (WhatsApp contact info, hero banners, site settings, safety notes).

                        ---

                        ## 2. Base URL & Environment

                        - **Development Base URL**: `http://localhost:5000/api`
                        - **Production Base URL**: `https://your-production-domain.com/api`

                        All backend routes are prefixed with `/api`.

                        ---

                        ## 3. Authentication & Authorization Strategy

                        Authentication uses **JSON Web Tokens (JWT)**:
                        - **Access Tokens**: Short-lived (e.g., 15-60 minutes), sent in the HTTP `Authorization` header.
                          ```http
                            Authorization: Bearer <accessToken>
                              ```
                              - **Refresh Tokens**: Long-lived (e.g., 7-30 days), stored securely to issue new access tokens via `/auth/refresh-token`.
                              - **User Roles**:
                                - `customer`: Public user access.
                                  - `admin`: Requires `admin` role claim to access endpoints prefixed with `/admin` or protected upload endpoints.

                                  ## 4. Standard API Response Format

                                  ### Success Response (`ApiResponse<T>`)
                                  ```json
                                  {
                                    "success": true,
                                      "message": "Operation completed successfully.",
                                        "data": { ... },
                                          "meta": { ... }
                                          }
                                          ```

                                          ### Paginated Response (`PaginatedResponse<T>`)
                                          ```json
                                          {
                                            "success": true,
                                              "message": "Items retrieved successfully.",
                                                "data": [ ... ],
                                                  "meta": {
                                                      "page": 1,
                                                          "limit": 12,
                                                              "totalItems": 40,
                                                                  "totalPages": 4,
                                                                      "hasNextPage": true,
                                                                          "hasPreviousPage": false
                                                                            }
                                                                            }
                                                                            ```

                                                                            ### Error Response (`ApiErrorResponse`)
                                                                            ```json
                                                                            {
                                                                              "success": false,
                                                                                "message": "Validation failed.",
                                                                                  "errors": {
                                                                                      "email": ["Email address is invalid."],
                                                                                          "password": ["Password must be at least 8 characters."]
                                                                                            },
                                                                                              "statusCode": 422,
                                                                                                "timestamp": "2026-08-04T19:44:00.000Z",
                                                                                                  "path": "/api/auth/register"
                                                                                                  }
                                                                                                  ```

                                                                                                  ## 5. HTTP Status Codes

                                                                                                  - `200 OK`: Request succeeded.
                                                                                                  - `201 Created`: Resource created successfully.
                                                                                                  - `400 Bad Request`: Malformed syntax or bad parameters.
                                                                                                  - `401 Unauthorized`: Missing, invalid, or expired JWT.
                                                                                                  - `403 Forbidden`: Authenticated user lacks `admin` permissions.
                                                                                                  - `404 Not Found`: Requested resource does not exist.
                                                                                                  - `409 Conflict`: Resource duplication (e.g., existing email or slug).
                                                                                                  - `422 Unprocessable Entity`: Input validation errors.
                                                                                                  - `500 Internal Server Error`: Unexpected backend failure.

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             ### 7.3 Admin Product Endpoints

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     ## 8. Backend Implementation Notes & Security Guidelines

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     1. **Password Security**: Use `bcrypt` (salt rounds >= 10) or `argon2`. Never return `password` field in user JSON responses.
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     2. **3D File Validation**: Validate the extension, MIME signature, and 100 MB maximum size for `.glb`, `.gltf`, `.stl`, `.obj`, and `.ply`. Preserve the original extension in the returned URL because the frontend selects its loader from it.
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     3. **CORS & Helmets**: Configure CORS headers allowing the frontend origin (`http://localhost:4200` in dev, production domain in prod).
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     4. **Soft Delete**: Product deletion should set `deletedAt = new Date()` so existing user order references or logs stay consistent.
