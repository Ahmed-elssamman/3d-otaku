# Product edit and publication safety

Ordinary product mutations now carry the revision of the record the administrator actually reviewed. The private product response includes `revision: number | null`; the editor sends that captured value as `expectedRevision` on PUT, list deletion sends it in the DELETE body, and the manufacturing panel supplies it for its minimal unpublish PUT. No extra GET silently substitutes a newer revision immediately before a write. Missing or invalid response revisions become `null` and block these actions. Duplication keeps its existing contract.

During a product save, the reactive controls and native editor fieldset are disabled. File-selection and gallery-removal handlers also reject programmatic invocation while an editor operation is busy. The save buttons, in-page navigation and upload controls cannot start a second change during the pending save. Completion restores editable controls and reapplies the existing manufacturing publication restriction; an inactive pending draft stays unpublished. A definite field-validation 422 leaves the original fields, including price zero and a null discount, available for correction.

Companion limits now match the backend's gallery count (30), media URL length (2,000 characters), specification length (500), and safety-note length (5,000). Over-limit input is retained and receives field feedback and a linked validation summary. Gallery file selection checks the existing distinct URLs and selected valid files before uploading; excess selections show the remaining capacity and send no upload. No selection or saved field is silently truncated.

Definite creation/update 422 responses use rejected-data guidance rather than uncertain-result copy. Known API field keys map to the form, including `image` → `mainImage` and `gallery` → `galleryImages`. Feedback uses known Arabic labels and guidance; arbitrary server error text and unsupported keys are not rendered. Each server rejection stays associated with its rejected field value, so correcting another field does not clear it. Empty optional fields, empty galleries, zero-priced inactive drafts and null discounts retain their existing payload semantics.

A stale revision or an uncertain update keeps the draft and blocks another save. **تحميل أحدث نسخة للمراجعة** only reads the current record and shows the server fields that changed; it does not overwrite local input or retry a write. **الاحتفاظ بتعديلاتي ومراجعة الحفظ** merges only fields changed locally since the original loaded snapshot onto the reviewed current record. Publication always takes the current server state, so republishing requires another deliberate control change. **تجاهل تعديلاتي واستخدام النسخة الحالية** explicitly discards the local edits. Both paths require another explicit save, using the reviewed revision; a later concurrent change can still be rejected normally. Failed reloads preserve the draft and remain blocked. A deleted product is not recreated automatically.

Deletion captures the selected list record before opening confirmation. Failed deletion requires an explicit current-list reload and another confirmation. This prevents an older confirmation from silently targeting a newer version. The `ApiService.delete` extension supports a typed optional request body without changing other callers.

Implementation is in the admin product form, control and models; `AdminProductService`; the products list; the manufacturing unpublish caller; and `core/api/api.service.ts`. Response-only revision, manufacturing and configuration metadata are excluded from ordinary product payloads. New UI state uses signals and the existing external template/control/style pattern.
