## Pacing the actual protection

The shared fixture retains the existing read-only `/api/health` guard: the global limit is **300/minute**, and a scenario starts only with at least **150 remaining**. Otherwise it waits for the reported reset plus one second and checks again within its bounded fixture timeout. A1, for example, retained the observed **144 remaining / 27-second wait** before its payment scenario. Business submissions are never silently retried.

The separate **30-per-900-second** authentication and submission limits require a longer pause between A and B. Each test saves `quota-evidence.json` under its own results directory. The observer records only timestamp, bucket, HTTP status and numeric limit/window/remaining/reset from genuine browser login/register or order/custom/contact POST responses. It awaits header reads and stores no raw headers, credentials, request bodies, receipts or tokens. It does not issue a probe POST or claim to capture direct API setup requests or aborted responses; a later real response provides the authoritative remaining quota.
