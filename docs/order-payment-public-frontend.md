`OrderPaymentSummary` is the shared contract used by public orders and the administrator payment snapshot. It exposes only `state`, `recordedCollected`, `recordedRefunded`, `recordedNet`, `balanceDue`, `credit`, and `shippingConfirmed`. All five monetary values are `number | null`, expressed in EGP. No payment entries, references, methods, actor identities, revisions, or internal notes belong in this contract.

The backend supplies the summary on order creation/replay, tracking, account lists, and administrator order responses. An older API response or a previously saved receipt can omit it; the frontend then displays **unavailable**, without inferring zero payments or unpaid status. `OrderService` normalizes API results and restored receipts into an explicit field whitelist. It requires exact safe integer piastres, collected minus refunded equal to the recorded net, mutually exclusive positive due/credit, and a balance only for confirmed shipping. Invalid/non-finite or inconsistent monetary/shipping data display unavailable. The UI does not calculate a balance from a provisional invoice.

| State | Visible Arabic label | Amount behavior |
| --- | --- | --- |
| `no-records` | لا توجد دفعات مسجلة | No money table or balance; explains that missing records do not prove nonpayment. This also covers a ledger whose movements were all corrected. |
| `shipping-unconfirmed` | الرصيد النهائي ينتظر تأكيد الشحن | Collected, refunded, and net recorded amounts only; final balance/credit withheld. |
| `recorded-balance` | الرصيد حسب الدفعات المسجلة | Recorded movements and server balance; positive credit has an explicit note that it has not thereby been refunded. |
| `settlement-review` | الطلب الملغى يحتاج مراجعة التسوية | Recorded movements only; cancellation does not automatically refund money or establish a final debt. |
| `unavailable` | ملخص الدفعات غير متاح | No numeric inference; asks the customer to refresh or contact the store. |

`OrderPaymentSummaryComponent` is a standalone component with external HTML/SCSS, a required signal input `summary: OrderPaymentSummary | null`, computed display state, static Arabic copy in its companion control file, and a named RTL section. It is shown in the saved cart receipt and expanded account order details, and is available for reuse by the administrator UI. It provides no payment collection action and makes no provider verification or “fully paid” claim.

The receipt and account details also show a separate native disclosure of the order item's stored public configuration. This does not change the payment summary contract or calculate payment from specifications. Private manufacturing snapshots are excluded from public order normalization. Invoice, configuration and payment lists are separate semantic elements; browser selectors must target the relevant section rather than every `dl` in the receipt.

Stable browser selector: `app-order-payment-summary section[aria-label="ملخص الدفعات المسجلة"]`. The state is `.summary-state`; the amount table uses semantic `dt`/`dd` pairs. Labels are `المبالغ المحصّلة المسجلة`, `المبالغ المستردة المسجلة`, `صافي المبالغ المسجلة`, `المتبقي حسب السجل`, and, for positive credit, `المبلغ الزائد حسب السجل`.
