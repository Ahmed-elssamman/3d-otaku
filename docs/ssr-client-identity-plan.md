## Implemented trust boundary

1. **Explicit SSR proxy addresses.** `STORE_TRUSTED_PROXY_ADDRESSES` accepts comma-separated literal IPv4/IPv6 addresses or CIDRs: IPv4 `/1`–`/32`, IPv6 `/1`–`/128`. Invalid configuration fails startup. Hostnames, named ranges, ports and zone identifiers are rejected. An empty list trusts no forwarding headers, including those arriving from loopback/private addresses; it still uses the canonical direct socket identity.
2. **Resolve from the socket before rendering.** `src/server-client-identity.ts` validates `IncomingMessage.socket.remoteAddress` and checks the explicit allowlist. Only a trusted socket with exactly one raw `X-Forwarded-For` header containing one valid IP can replace the socket identity. Missing, malformed, repeated, chained, oversized or port-bearing values fall back to the socket. `Forwarded` and `X-Real-IP` are ignored. Missing or invalid socket evidence yields null. IPv6 is canonicalized; mapped IPv4 becomes ordinary IPv4. Configured mapped IPv6 CIDRs retain their original IPv6 prefix semantics.
3. **Keep context per render.** `StorefrontRequestContext` contains only `clientIp: string | null`. The Node entry passes this context to `AngularNodeAppEngine.handle`; `REQUEST_CONTEXT` supplies a server-only token. There is no process-global current-client variable. Plain `renderStorefront(Request)` remains context-free and cannot infer identity from its headers. `renderStorefrontFromNodeRequest(IncomingMessage)` is the shared Node adapter for `reqHandler` and the local preview. After resolving the socket identity, both rendering entry points remove `Forwarded`, `X-Real-IP` and all `X-Forwarded-*` headers before Angular handles the web request. This also prevents an untrusted `X-Forwarded-Prefix` from altering framework redirects. Angular's `trustProxyHeaders: false`, hostname validation and explicit public-origin configuration remain separate from IP trust.
4. **Forward only anonymous public reads.** `serverClientIpInterceptor` replaces caller-supplied XFF only for GET requests to the exact configured `API_ORIGIN` whose path passes `isPublicCatalogUrl`: product/category reads and public settings. It excludes URL credentials, authorization/cookie headers and credential-bearing requests. Private endpoints, external origins, browser execution and context-free rendering do not receive a verified identity header. Incoming document credentials are not copied into API requests; the context is not stored in HTML, transfer state or browser persistence.
5. **Trust exact backend ingress addresses.** `TRUSTED_PROXY_ADDRESSES` is a separate backend allowlist for the actual edge/SSR egress addresses or CIDRs. Empty means no proxy trust. Legacy `TRUST_PROXY_HOPS` may be absent, blank or exactly `0` after trimming; any other value fails with migration guidance. Express follows the nearest-to-farthest trusted proxy chain, and express-rate-limit retains its existing IP/IPv6 grouping, quotas and stores. No quota exemption or raised limit is introduced.

The SSR boundary deliberately expects an edge that overwrites XFF with one client IP; it does not infer an arbitrary incoming chain. Multiple permitted edge addresses can use that same contract. Backend chain handling is separate. Production must restrict access to the intended listeners and configure the actual edge/SSR addresses; an allowlist cannot make an unsanitized header trustworthy.

The loopback preview forces its SSR trusted-proxy list empty even if a parent environment supplies one, uses the shared Node request adapter for SSR and strips inbound IP claims before proxying API requests. It supplies only its own validated host/protocol forwarding values to the API. It is a local validation tool, not a production edge configuration. A deployed adapter must use the same verified Node context path; passing a fabricated request context bypasses the stated boundary.

## Framework and source evidence

Angular 21 supports `AngularNodeAppEngine.handle(request, requestContext)` in `node_modules/@angular/ssr/types/node.d.ts`. Its Node implementation forwards that context unchanged, and the renderer provides it as `REQUEST_CONTEXT` for each SSR request. The token is null outside SSR. Node's existing `net.isIP` and `BlockList` supply address validation and matching without another dependency.

Implementation is in `src/server-client-identity.ts`, `src/server.ts`, `src/app/core/api/server-client-ip.provider.ts` and `src/app/core/interceptors/server-client-ip.interceptor.ts`. The backend loads its explicit proxy policy through `outako/backend-api/src/config/index.js`. Public-origin and HTTP transfer-cache configuration remain in `src/app/app.config.server.ts`.
