The contact route now has separate Arabic RTL forms for custom printing ideas and ordinary questions. It follows the existing warm white/green storefront design and uses the store's configured contact channels. Descriptions, optional technical details and realistic review steps replace the previous dark English page. No turnaround promises, payment confirmation or unsupported manufacturing materials are invented.

Custom requests validate Egyptian mobile numbers (including Arabic digits), whole quantities, useful text, HTTPS references and design permission. A written idea does not require a link. Switching back to a written idea clears the hidden reference and its requirement. Ordinary questions require a reply email and allow an optional Egyptian mobile number. Whitespace around email addresses is trimmed before validation.

Both forms call the real API. A success screen appears only after a valid acknowledgement containing a saved record ID and actual CUSTOM-/MESSAGE- reference. An uncertain submission retains its original body and Idempotency-Key across reload; changed form contents cannot replace that attempt. Explicit recovery resends the original saved request without losing later edits, even if those edits are currently invalid. Only an initial definite validation rejection or a valid matching acknowledgement clears the saved attempt. A generic later 422, network failure or malformed receipt keeps it unresolved. Unavailable or malformed tab storage blocks replacement submission. Pending and receipt views distinguish the original request from retained edits; ordinary form-validation summaries stay hidden while that request awaits recovery. The optional WhatsApp continuation uses only safe reference context and opens on an explicit click.

WhatsApp links now normalize configured Egyptian mobile numbers to international digits before constructing `wa.me` URLs. For example, the legacy local format `01012345678` becomes `201012345678`; equivalent Arabic-digit and international inputs give the same destination. Invalid, overseas or missing settings produce no link. The service uses the current settings without changing the stored number. Order-support links now receive the existing Arabic status label from the orders page, preserving the order reference while omitting customer contact/address details, internal IDs and raw status codes. Custom-request support text continues to exclude private design-reference URLs and notes. No message is sent automatically.

The 3D preview now uses a neutral background, Arabic controls and larger color targets. Color changes are explicitly labelled as preview-only. Decorative fire/particle rendering was removed; rendering pauses off-screen, on hidden tabs and on errors. Reloads invalidate old callbacks, reset the color selection and release the previous scene. Rotating a model refits its display base. Fullscreen exit remains available after a rendering failure. Product photographs and ordering remain available independently of the optional viewer.
